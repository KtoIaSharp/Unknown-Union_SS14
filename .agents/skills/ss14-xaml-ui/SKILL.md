# SS14 / RobustToolbox XAML UI

XAML here is **not WPF**. It is RobustToolbox's XamlIL: no data binding, no designer,
no `x:Bind`, no styles inheritance from WPF. Layout is done with
`Robust.Client.UserInterface.Controls` containers, and all behaviour lives in the
code-behind `partial` class.

## Non-negotiable rules

1. **Root element is your own class**, referenced through `xmlns:ui`, or the base type
   when you inherit directly. Both patterns exist in this repo:
   - direct base: `<DefaultWindow xmlns="https://spacestation14.io" MinSize="650 290">`
     (see `Content.Client/Access/UI/IdCardConsoleWindow.xaml`)
   - own prefix: `<ui:SecApartmentWindow xmlns:ui="clr-namespace:Content.Client.Corvax.SecApartment" ...>`
     (see `Content.Client/Corvax/SecApartment/SecApartmentWindow.xaml`)
2. **Code-behind must be `partial` and carry `[GenerateTypedNameReferences]`.**
   The first statement of the constructor is `RobustXamlLoader.Load(this);`.
3. **No csproj edits.** `Content.Client/Content.Client.csproj` imports
   `RobustToolbox/MSBuild/XamlIL.targets`, which globs `**/*.xaml` as
   `EmbeddedResource` + `AdditionalFiles` and excludes it from default items.
   Just drop `Foo.xaml` next to `Foo.xaml.cs`.
4. **Every user-visible string goes through `{Loc 'key'}`**, never a literal and never
   `Loc.GetString` in XAML. New keys must be added to **both**
   `Resources/Locale/ru-RU/...` and `Resources/Locale/en-US/...`.
5. **Only use StyleClasses that already exist** in the active stylesheet. Inventing a
   class silently produces an unstyled control. When in doubt, use the plain control
   (`<Label>`, `<Button>`, `<LineEdit>`) — the base stylesheet styles types by default,
   which is what most repo windows rely on.
6. **Never hardcode colours if the window already gets them from the stylesheet.**
   `Modulate`/`FontColorOverride` are for deliberate accents only.
7. Behaviour, event subscription and state updates go in the code-behind. XAML has no
   event syntax in this codebase (`OnPressed += ...` in C#).

## Minimal window

`TransmitterWindow.xaml`:

```xml
<DefaultWindow xmlns="https://spacestation14.io"
               Title="{Loc 'radio-transmitter-title'}"
               MinSize="350 170">
    <BoxContainer Orientation="Vertical" SeparationOverride="4">
        <Label Name="CurrentLabel" />
        <Control MinSize="0 6" />
        <Label Text="{Loc 'radio-enter-frequency'}" />
        <LineEdit Name="FreqInput" PlaceHolder="{Loc 'radio-frequency-placeholder'}" />
        <Button Name="SetButton" Text="{Loc 'radio-set-frequency'}" />
    </BoxContainer>
</DefaultWindow>
```

`TransmitterWindow.xaml.cs`:

```csharp
using Robust.Client.AutoGenerated;
using Robust.Client.UserInterface.Controls;
using Robust.Client.UserInterface.CustomControls;
using Robust.Client.UserInterface.XAML;

namespace Content.Client._UU.Radio;

[GenerateTypedNameReferences]
public sealed partial class TransmitterWindow : DefaultWindow
{
    public event Action<string>? OnSubmitted;

    public TransmitterWindow()
    {
        RobustXamlLoader.Load(this);

        SetButton.OnPressed += _ =>
        {
            var text = FreqInput.Text.Trim();
            if (!string.IsNullOrWhiteSpace(text))
                OnSubmitted?.Invoke(text);
        };
    }
}
```

`Name="X"` becomes a typed field. Add `Access="Public"` only when an outside class
(usually the `BoundUserInterface`) has to touch the control.

## `DefaultWindow` specifics

`DefaultWindow` sets `Contents = ContentsContainer` in its own constructor
(`RobustToolbox/Robust.Client/UserInterface/CustomControls/DefaultWindow.xaml.cs:63`),
so children declared in your XAML land in `ContentsContainer` automatically — you do
**not** write `ContentsContainer.AddChild(...)` any more when converting from code.
`Title`, `MinSize`, `SetSize` are settable from XAML.

## Layout vocabulary used in this repo

`BoxContainer` (`Orientation="Vertical|Horizontal"`, `SeparationOverride`), `GridContainer`
(`Columns`), `ScrollContainer`, `PanelContainer` (+ `PanelContainer.PanelOverride` with
`gfx:StyleBoxFlat`), `TabContainer`, `Control` as spacer (`MinSize="0 8"`),
`TextureRect` (`TexturePath`), `TextureButton`, `LineEdit`, `Button`, `CheckBox`,
`OptionButton`, `ItemList`, `StripeBack`. Custom content controls come in via
`xmlns:controls="clr-namespace:Content.Client.UserInterface.Controls"`.

Frequently needed attributes: `HorizontalExpand`, `VerticalExpand`, `HorizontalAlignment`,
`VerticalAlignment`, `Margin="left top right bottom"`, `MinSize`, `SetHeight`/`SetWidth`,
`RectClipContent`, `MouseFilter` (`Stop` for windows).

## StyleClasses

A class exists only if it is registered by a stylesheet or sheetlet. Names reach
`.Class(...)` in three different ways, and **checking only one of them gives wrong
answers** — `AngleRect` is declared as `public const string ClassAngleRect` in
`StyleNano.cs:170`, so a literal string grep misses it; many others arrive as
`.Class(StyleClass.Foo)`.

Regenerate the authoritative list (95 names in this working copy) with:

```powershell
$constMap = @{}
Get-ChildItem 'Content.Client/Stylesheets' -Recurse -File -Filter *.cs | ForEach-Object {
    [regex]::Matches([IO.File]::ReadAllText($_.FullName), 'public const string (\w+)\s*=\s*"([^"]+)"') |
        ForEach-Object { $constMap[$_.Groups[1].Value] = $_.Groups[2].Value }
}
$registered = [System.Collections.Generic.HashSet[string]]::new()
Get-ChildItem 'Content.Client/Stylesheets' -Recurse -File -Filter *.cs | ForEach-Object {
    $txt = [IO.File]::ReadAllText($_.FullName)
    [regex]::Matches($txt, '\.Class\(\s*"([^"]+)"\s*\)') |
        ForEach-Object { $registered.Add($_.Groups[1].Value) }
    [regex]::Matches($txt, '\.Class\(\s*([\w\.]+)\s*\)') | ForEach-Object {
        $id = ($_.Groups[1].Value -split '\.')[-1]
        if ($constMap.ContainsKey($id)) { $registered.Add($constMap[$id]) }
    }
}
$registered | Sort-Object
```

Verified-registered classes that are useful for window work: `ConsoleHeading`,
`ConsoleSubHeading`, `ConsoleText`, `LabelSubText`, `LabelHeading`, `LowDivider`,
`HighDivider`, `PdaBackground`, `PdaBackgroundRect`, `PdaBorderRect`,
`PdaContentBackground`, `PdaWindowFooterText`, `WindowFooterText`, `AngleRect`,
`ButtonColorRed`, `ButtonColorGreen`, `ButtonSmall`, `windowHeaderAlert`.

Known trap: **`SecApartmentWindow.xaml` uses `ConsoleHeadingBig`, `ConsoleSubText`,
`ConsoleLineEdit` and `ButtonRed`, none of which are registered anywhere** — those
elements silently render unstyled. Do not copy class names out of a window without
checking them with the command above.

Style names that need a bespoke look (as `SecApartmentStyles` does) can be registered
from C# with `StylesheetHelpers` and merged into the active stylesheet; copy that pattern
rather than inventing names in XAML.

## Localization

- XAML: `Text="{Loc 'some-key'}"`, `PlaceHolder="{Loc 'some-key'}"`,
  `Title="{Loc 'some-key'}"`.
- C#: `Loc.GetString("some-key")`, with arguments as
  `Loc.GetString("key", ("name", (object)value))`.
- FTL files live under `Resources/Locale/<culture>/<area>/<file>.ftl`.
  This fork keeps `ru-RU` and `en-US`; add the key to both or the English client shows
  the raw key.
- Escape untrusted text before it reaches markup: `FormattedMessage.EscapeText(...)`.

### Entity names and descriptions do NOT use keys referenced from YAML

The engine resolves them itself: `LocalizationManager.Entity.cs:61` builds
`ent-{prototypeId}` (or `prototype.CustomLocalizationID`) and reads the Fluent
**message attributes** for the rest:

```
ent-RadioTransmitter = Передатчик
    .desc = Создаёт и передаёт на радиочастотах...
```

Consequences worth remembering:

- A `name: some-loc-key` in a prototype is a **literal string**, not a lookup. Keys like
  `radio-transmitter-name` referenced from YAML never apply — that is dead localization.
- The YAML `name:`/`description:` values stay as English fallbacks (upstream convention);
  Russian comes from `ent-<Id>` in `ru-RU`.
- Localization is inherited along the prototype's parent chain, so a child entity can
  override only `.desc` while keeping the parent's name.

## Sprites in the UI

Two ways to show art; pick deliberately.

**1. `EntityPrototypeView` — prefer this for game objects.** It renders an entity's real
sprite, directional RSIs included, exactly as in the world, so the terminal shows the same
device the player placed:

```xml
<EntityPrototypeView Name="DeviceView" Scale="1.5 1.5" MinSize="48 48" />
```

```csharp
DeviceView.SetPrototype("RadioTransmitter"); // takes EntProtoId?
```

Defined in `RobustToolbox/Robust.Client/UserInterface/Controls/EntityPrototypeView.cs`
(`: SpriteView`, `SetPrototype(EntProtoId?)`). Real usages:
`Content.Client/Construction/UI/FlatpackCreatorMenu.xaml` (`Scale="4 4"`),
`Content.Client/Silicons/Borgs/BorgSelectTypeMenu.xaml`, `ConstructionMenu.xaml.cs`.

**2. `TexturePath` on `TextureRect` for plain files.** `/Textures/.../file.rsi/state.png`
is a valid resource path (`ResourceCache` special-cases `.rsi/`) and is used in
prototypes, e.g. `Resources/Prototypes/Parallaxes/test.yml`. Caveat: for a state with
`directions: 4` you get the raw sheet, not one frame — use `EntityPrototypeView` there.

### RSI facts to know before touching art

- `meta.json` declares `size` (one frame, in pixels) and `states`.
- **Width = `size.x` × directions, height = `size.y` × frames.** Verified:

  | file | size | dirs | png | layout |
  |---|---|---|---|---|
  | `_UU/transmitter.rsi/icon.png` | 32×32 | 4 | 128×32 | 1 frame, 4 dirs |
  | `Tiles/Planet/lava.rsi/lava0.png` | 32×32 | 4 | 128×128 | 4 frames, 4 dirs |
  | `Structures/Wallmounts/service_light.rsi/glow.png` | 32×32 | 4 | 128×64 | 2 frames, 4 dirs |

- A directional state follows the entity's rotation when the layer is not `noRot` — the
  intercom proves the pattern:
  `Resources/Prototypes/Entities/Structures/Wallmounts/WallmountMachines/intercom.yml`
  declares `- type: Sprite` + `noRot: false` and one layer, nothing else.
- There is **no automated Aseprite → RSI step** in this repo. What exists:
  `Tools/SS14 Aseprite Plugins/*.lua`, `Tools/SS14 Aseprite Templates/IconSmoothingTemplate.aseprite`,
  plus two ad-hoc helpers — `Tools/fix_rsis.py` (drops `meta.json` states whose PNG is
  missing; note it contains a hardcoded absolute path) and `Tools/sync_textures.py`
  (interactive copy of exported PNGs over the repo, dry-run by default).

## Verification loop (there is no designer)

1. `dotnet build Content.Client/Content.Client.csproj` — XamlIL failures surface here
   (unknown property, missing control type, bad markup extension, duplicate field).
2. Run the game and open the UI: layout bugs, unstyled controls and clipped text only
   show at runtime.
3. RSIs of any new sprite used by the UI must pass `validate-rsis.yml`
   (`meta.json` with correct `states`, `directions`, `delays`).
4. Line endings: files in `Content.Client/_UU`, `Content.Shared/_UU`,
   `Content.Server/_UU` are LF; most upstream `Content.Client` files are CRLF.
   Match the file you edit — the repo has a `check-crlf` workflow.

## Anti-patterns seen in real code

- Duplicating class names: when converting `Foo.cs` to XAML, **delete the old `.cs`**,
  otherwise two partial declarations of `Foo` collide.
- Building a whole layout in the constructor with manual `new Label { Text = ... }` —
  that is the thing this skill replaces; keep only dynamic per-item controls in code.
- Concatenating user text into `Text` without escaping, or into markup strings.
- Copying a StyleClass from another game version: only the list above is verified here.
